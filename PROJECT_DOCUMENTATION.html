1. Executive Summary

VetAI Diagnostics is a full-stack web platform that helps livestock owners and veterinarians diagnose cattle diseases through two complementary AI-driven paths:

  1. Image-based diagnosis — a user uploads a photo of a cow; a deep-learning CNN (MobileNetV2 transfer learning) classifies it into one of three trained classes (Foot-and-Mouth, Lumpy Skin Disease, Healthy).
  2. Symptom-based diagnosis — a user selects observed symptoms from a list of ~93 clinical markers; a rule-based scoring engine (built from a CSV dataset of ~2,000 records) ranks the most likely diseases.

For both paths, the system then calls the Google Gemini API in real time to generate rich, up-to-date medical guidance — symptoms, severity, treatment steps, prevention, recommended antibiotics, and contagion status — with a local JSON file acting as a fallback when the API is unavailable. A third feature, Vet AI Chat, provides a conversational veterinary assistant backed by Gemini through a secure server-side proxy.

2. What the Project Does

🖼️ Image Diagnosis

Upload a cow image → CNN predicts disease + confidence → Gemini enriches with medical detail → stored as a detection record → shown in a clinical report UI.

🩺 Symptom Diagnosis

Pick symptoms → dataset scoring engine ranks top-5 diseases → Gemini enriches the best match → saved & displayed with treatment/prevention/medicines.

💬 Vet AI Chat

Conversational assistant. Frontend sends message + history to a Django proxy, which calls Gemini with a veterinary system prompt. Chat history persists in the browser's localStorage.

📊 Dashboard & History

Per-user statistics (total scans, average confidence, disease distribution, severity stratification) rendered with Recharts, plus a full medical-history list of past detections.

4. System Architecture

A classic decoupled SPA + REST architecture. The React client talks to the Django REST API over JWT-authenticated HTTP. Django orchestrates three "intelligence" sources: the local TensorFlow model, the pandas-driven symptom engine, and the external Gemini API.

6. Backend Deep Dive (Django)

6.1 Project configuration (server/settings.py)

  • Apps: accounts, animal, ml_model + DRF, SimpleJWT, corsheaders.
  • Database: MySQL, configured via environment variables (DB_NAME, DB_HOST, etc.) with utf8mb4 charset.
  • Auth: Default authentication class is JWTAuthentication. Access token lives 24h, refresh token 7 days, with rotation enabled.
  • CORS/CSRF: Whitelists the Vercel frontend + localhost; allows all origins when DEBUG=True.
  • Static: WhiteNoise serves compressed static files (production-friendly).
  • Media: Uploaded images saved under media/uploads/.
  • Logging: Console logging; the animal logger runs at DEBUG level (heavy diagnostic logging throughout the views).

6.3 Image-detection request lifecycle (DetectAnimalAPIView.post)

  1. Read request.FILES['image']; validate it exists, is ≤ 10 MB, and has an allowed extension (.jpg/.jpeg/.png/.gif).
  2. Write the upload to a cross-platform NamedTemporaryFile.
  3. Run prediction through the singleton DiseaseDetectionModel (loads the .h5 lazily, caches it).
  4. Normalize the predicted label and validate it is one of foot-and-mouth / lumpy / healthy.
  5. Call get_disease_info(..., use_cache=False, force_fresh=True) to fetch real-time Gemini medical data.
  6. If Gemini fails → fall back to disease_info.json → else a hardcoded "consult a vet" default.
  7. Persist an AnimalDetection row with all fields, clean up the temp file, and return the serialized record plus a data_source marker and any low-confidence warning.

7. Machine Learning Pipeline

7.1 Model architecture (ml_model/disease_detector.py)

Transfer learning on a frozen MobileNetV2 backbone with a custom classification head:

Sequential([
  Input(shape=(224, 224, 3)),
  Rescaling(1./255),                  # normalization done INSIDE the model
  MobileNetV2(include_top=False, weights='imagenet', trainable=False),
  GlobalAveragePooling2D(),
  Dense(256, activation='relu'), Dropout(0.5),
  Dense(128, activation='relu'), Dropout(0.3),
  Dense(num_classes, activation='softmax'),
])
# optimizer=Adam(1e-3), loss=categorical_crossentropy
Key design choice: rescaling (÷255) is a layer inside the model, so the ImageDataGenerator uses rescale=None and the inference code does not divide by 255. This keeps training and prediction preprocessing identical — a common source of bugs that the author deliberately avoided.

7.2 Training

  • Data: images organized in one folder per disease class.
  • Augmentation: rotation, shifts, horizontal flip, zoom, shear (no rescale).
  • Class imbalance: handled via compute_class_weight('balanced', ...).
  • Callbacks: EarlyStopping (patience 10), ReduceLROnPlateau, ModelCheckpoint (best val accuracy).
  • Evaluation: prints validation loss/accuracy, a classification report, and a confusion matrix.
  • Run via: python manage.py train_model --epochs 50 --batch-size 32.

7.3 Saved artifacts & trained classes

Three formats are saved for portability: cow_disease_detector.h5, a _savedmodel directory (TF SavedModel), and the class index map as both .pkl and .json. The currently trained classes are:

7.4 Robust model loading (inference)

The inference wrapper (animal/views.py → DiseaseDetectionModel) is a singleton and contains an unusually defensive loader to survive TensorFlow/Keras version mismatches between the machine that trained the model and the server running it. It layers several fallbacks:

  1. Patch Operation.from_config for signature changes across TF versions.
  2. Custom FixedBatchNormalization (handles axis as list vs int) and FixedInputLayer (maps legacy batch_shape → input_shape).
  3. Try load_model(safe_mode=False, custom_objects=...).
  4. Fallback: read the raw H5 JSON config with h5py, normalize legacy keys (batch_shape, DTypePolicy), rebuild via model_from_json, then load_weights.
  5. Further fallbacks via tf.compat.v1 and a clear "please retrain" error message.
This complexity exists because the model was trained with one TF version and may be loaded under another (e.g. on Railway). It is robust but brittle — the cleanest long-term fix is to retrain and serve under a single, pinned TensorFlow version.

7.5 Prediction post-processing

The image is loaded at 224×224, predicted, and the softmax outputs are mapped to the class names. Only the three valid disease keys are surfaced. Confidence thresholds (<0.5, <0.4) trigger log warnings and a user-facing "low confidence — verify with a vet" message in the response.

8. Gemini AI Integration

The file animal/gemini_service.py is the heart of the "real-time medical knowledge" feature. It calls Google's Generative Language API and returns structured JSON describing a disease.

Configuration (env-driven)

VariableDefaultPurpose
GEMINI_API_KEY(empty)API key; if unset → graceful error
GEMINI_MODELgemini-2.5-flashPrimary model
GEMINI_FALLBACK_MODELS2.5-flash, 2.0-flash, flash-latestTried in order
GEMINI_TIMEOUT_SECONDS35Per-request timeout

How it works

  1. Prompt engineering: builds a strict prompt demanding only valid JSON with a fixed schema (name, severity, symptoms[], treatment[], prevention[], contagious, antibiotics[]). Uses responseMimeType: application/json and safety settings.
  2. Multi-model / multi-version retry: iterates over candidate models and both the v1beta and v1 API base URLs, handling 404 / 403 / 429 / timeouts distinctly.
  3. Robust JSON parsing: strips markdown fences, then uses gemini_json_fix.safe_parse_gemini_response / repair_json to recover from truncated or malformed JSON. If the response is incomplete (MAX_TOKENS), it retries with a "compact" prompt.
  4. Defaults & backfill: missing fields are filled from the local disease_info.json or sensible "consult a vet" defaults so the UI is never empty.
  5. Source tagging: every result carries an internal _source (gemini_api, json_fallback, gemini_error, ...) used by the views to decide warnings.

Errors are sanitized (the API key is redacted from any error text via _sanitize_error_text) and a custom print() wrapper strips non-ASCII so emoji logs don't crash Windows consoles.

Note: gemini_service.py defines get_disease_info twice — the second definition (line ~614) shadows the first. Both behave similarly (Gemini-first, then fallback), but only the second is actually used. Worth consolidating into one function.

Vet Chat proxy (VetChatAPIView)

Keeps the API key server-side. It builds a veterinary "system prompt", appends the last 10 messages of conversation history, and forwards to Gemini with temperature 0.7. The reply text is returned to the React chat widget. History is stored client-side in localStorage.

9. Symptom-Based Diagnosis Engine

Implemented in animal/dataset_processor.py as a singleton that loads CSV data once.

  • Dataset: server/Dataset/Training.csv (~2,043 rows) and Testing.csv. Each row is a one-hot vector of ~93 symptom columns plus a prognosis (disease) label.
  • Loading: reads all CSVs, builds a disease→symptom frequency map and a symptom→disease reverse index, and a sorted, human-formatted list of symptoms for the UI.
  • Scoring (diagnose): for each disease it counts matched symptoms (using substring matching after normalization) and computes a blended confidence: confidence = 0.6 × match_ratio + 0.4 × symptom_coverage. Returns the top-N (default 5).
  • Enrichment: the best match is then passed to Gemini (with the user's symptoms as context) so treatment / prevention / medicines reflect live data; results are saved as a SymptomDiagnosis row.
This engine is heuristic (keyword overlap), not a trained classifier — fast, transparent, and dataset-driven, but sensitive to symptom naming. It complements rather than competes with the CNN.

12. Authentication & Security

Flow

SignUp ─POST /api/register/─▶ create User SignIn ─POST /api/token/───▶ { access, refresh } ──▶ stored in localStorage Every request ── Authorization: Bearer <access> ──▶ JWTAuthentication 401 ──▶ client clears token & redirects to /signin ProtectedRoute ──▶ blocks "/" if no access_token present

Implemented protections

  • JWT access/refresh with rotation; passwords hashed by Django; password validators enabled.
  • File-size (10 MB) and file-type validation on uploads.
  • CORS + CSRF trusted-origin allow-lists; secure cookies when not in DEBUG.
  • Gemini API key kept server-side; error strings sanitized of the key.
  • Per-user data isolation — every query filters by request.user.
Security caveats to address before production: the default SECRET_KEY and DB password ('12345') are hardcoded fallbacks in settings.py; DEBUG defaults to True (which also enables CORS_ALLOW_ALL_ORIGINS). These must be overridden by environment variables in any real deployment. There is also no rate limiting on the auth or detection endpoints.

13. Frontend Deep Dive (React)

App.jsx defines three routes: /signup, /signin, and / (wrapped in ProtectedRoute). The protected home renders Home.jsx, a tabbed dashboard with a sticky header, responsive sidebar, and six tabs. State (activeTab, latestDetection, refreshTrigger) is lifted into Home so a successful diagnosis auto-switches to the Results tab.

13.3 Conventions & design language

  • State management: React Query for server state + mutations; local component state otherwise (no Redux).
  • API base URL from import.meta.env.VITE_API_BASE_URL with a localhost fallback.
  • Heavy Tailwind utility styling — a polished, "neural / clinical" aesthetic (gradients, blur, rounded-3xl cards, scan animations).
  • Icons via lucide-react; charts via recharts.
Two near-duplicate API config files exist: src/config/api.js (env-aware, used by most components) and src/api/index.js (hardcoded localhost). Some components also inline the base URL directly. Consolidating to a single config module would reduce drift.

14. Key User Flows

Image diagnosis (end to end)

User picks image → ImageDiagnosis (FormData) → POST /api/animal/detect/ → temp file → CNN.predict() → label + confidence → get_disease_info(force_fresh) → Gemini (or fallback JSON) → save AnimalDetection → response.data → Home.handleDiagnosisSuccess → switch to Results tab → DiseaseResults renders

Symptom diagnosis

Select symptoms → POST /api/diagnose/ {symptoms, animal_name, age, notes} → DatasetProcessor.diagnose() top-5 → Gemini enriches best match → save SymptomDiagnosis → results[] + saved_diagnosis → ranked cards + Results tab

16. Code Observations & Notes

Honest, constructive notes from reading the codebase — useful for a viva / report's "limitations & future work" section.
