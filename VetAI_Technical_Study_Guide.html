Foundation

1. Project ek nazar mein

VetAI Diagnostics ek web platform hai jo jaanwaron (cattle/cows) ki bimari detect karta hai aur uska ilaaj/treatment bhi batata hai. Farmer ko mehngi/door ki vet visit se pehle ek instant second opinion milta hai.

System teen tarah ki "intelligence" use karta hai:
  1. Image se detection (Deep Learning / CNN): Jaanwar ki photo upload karo → ek trained MobileNetV2 model batata hai bimari + confidence %.
  2. Symptoms se diagnosis (Rule-based matching): Photo na ho to symptoms select karo → ek matching algorithm sab se milti-julti bimari nikaalta hai.
  3. Treatment info + Vet Chat (Gemini AI): Bimari ka naam mil jaane ke baad Google Gemini se real-time symptoms, treatment, antibiotics, prevention aata hai. Saath mein ek vet chatbot bhi hai.

5. Symptom Diagnosis Flow (/api/diagnose/)

Yeh path deep learning use nahi karta — yeh ek scoring/matching algorithm hai. Examiner ye difference zaroor pooch sakta hai.

  1. Symptoms list: frontend pehle GET /api/symptoms/ call karta hai → DatasetProcessor Training.csv ke columns parh kar 93 symptoms return karta hai.
  2. User selection: user kuch symptoms tick karta hai → POST /api/diagnose/ with {"symptoms":[...]}.
  3. Matching (DatasetProcessor.diagnose): har bimari ke known symptoms se input symptoms match kiye jaate hain (substring matching), phir score nikalta hai: 
    # match_ratio  = kitne input symptoms match hue / total input
# coverage     = matches / us disease ke kul symptoms
confidence = (match_ratio * 0.6) + (coverage * 0.4)
  4. Top 5: sab bimariyan confidence se sort hoti hain, top 5 return.
  5. Treatment: sab se best match ke liye Gemini se treatment/prevention/medicines aate hain.
  6. Save: ek SymptomDiagnosis row ban-ti hai (input symptoms, matched disease, match_rate, treatment, etc.).
Do engine kyun? Image hamesha available nahi hoti (kabhi sirf symptoms pata hote hain), aur image model sirf 3 classes janta hai. Symptom engine 26 bimariyon ko cover karke gap bharta hai. Dono complementary hain.

Machine Learning — yahan se sab se zyada sawaal aate hain

7. MobileNetV2 kya cheez hai?

MobileNetV2 Google ka banaya hua ek Convolutional Neural Network (CNN) architecture hai jo specially mobile / low-resource devices ke liye design hua. Yeh "accuracy" aur "speed/size" ke beech behtareen balance deta hai.

Aam zubaan mein CNN kya hai?

CNN ek aisa network hai jo image ko layer-by-layer dekh kar patterns seekhta hai: pehli layers simple cheezein (edges, colours, lines), agli layers complex cheezein (shapes, texture, "lumpy skin jaisa pattern"). Aakhir mein yeh decide karta hai ke image kis class ki hai. Bilkul jaise ek vet experience se seekhta hai ke "yeh daane lumpy skin disease ke hain".

MobileNetV2 special kyun? (ye points viva mein bolo)

  • Depthwise Separable Convolutions: normal convolution ko do chhoti steps mein torta hai → bohot kam parameters & computation (≈ 3.4M params), lekin accuracy lagbhag barqaraar.
  • Lightweight & fast: file sirf ~13MB, prediction tezi se (CPU pe bhi chal jata hai) — farmer ke liye practical.
  • Pre-trained on ImageNet: pehle se 1.4 million images (1000 classes) pe train hai → general visual features already aata hai → hamein chhote dataset pe bhi acha result milta hai (transfer learning).
  • Inverted residuals + linear bottlenecks: (advanced) information ko efficiently flow karne deta hai bina zyada compute ke.
Alternatives kyun nahi? ResNet50 / VGG16 zyada bhaari (params/size bohot zyada) — chhote dataset aur low-cost deployment ke liye overkill aur slow. Scratch se CNN banate to itne chhote dataset pe overfit ho jata. Is liye MobileNetV2 + transfer learning best fit tha.

8. Transfer Learning (model ki actual architecture)

Transfer learning ka matlab: ek already-trained network ka "general knowledge" reuse karna, aur upar sirf apni problem ke liye chhota sa hissa naya train karna. Faida: kam data chahiye, training fast, accuracy achi.

Hamara model (disease_detector.py → build_model) aise bana hai:

model = Sequential([
    Input(shape=(224, 224, 3)),       # RGB image
    Rescaling(1./255),                  # pixels 0-255 → 0-1 (andar hi)
    MobileNetV2(weights='imagenet',      # pre-trained base
                include_top=False,
                trainable=False),          # BASE FROZEN — wapas train nahi
    GlobalAveragePooling2D(),               # features → ek vector
    Dense(256, activation='relu'),
    Dropout(0.5),                       # overfitting roko
    Dense(128, activation='relu'),
    Dropout(0.3),
    Dense(num_classes, activation='softmax') # 3 classes → probabilities
])
model.compile(optimizer=Adam(lr=0.001),
              loss='categorical_crossentropy',
              metrics=['accuracy'])

9. Dataset ko train kaise kiya (step-by-step)

Training command: python manage.py train_model --dataset "<path>" --epochs 50. Andar yeh hota hai (DiseaseDetectionModel.train):

  1. Dataset structure: har bimari ek folder, us folder mein us bimari ki images: 
    dataset/
├── foot-and-mouth/   img1.jpg ...
├── lumpy/            img1.jpg ...
└── healthy/          img1.jpg ...
    Folder names hi class names ban-te hain; num_classes = folders ki ginti (automatic).
  2. Train/Validation split: validation_split=0.2 → 80% data training, 20% validation (model ko check karne ke liye jo usne dekha nahi).
  3. Data Augmentation (ImageDataGenerator): training images ko thoda randomly badalte hain taa ke model zyada robust bane aur ratta na maare:
    • rotation_range=20 (20° tak ghumao)
    • width/height_shift=0.2 (idhar-udhar shift)
    • horizontal_flip=True (mirror)
    • zoom_range=0.2, shear_range=0.2
    Note Yahan rescale=None — kyun ke rescaling model ke andar hai (consistency).
  4. Class weights (imbalance handle): agar kisi bimari ki images kam hain to compute_class_weight('balanced') se us class ko zyada weight milta hai — taa ke model bari class ki taraf biased na ho.
  5. Callbacks (smart training):
    • EarlyStopping(patience=10, restore_best_weights=True) — agar validation loss 10 epochs tak improve na ho to ruk jao, aur sab se acha version wapas le lo. (Overfitting se bachata hai.)
    • ReduceLROnPlateau(factor=0.5, patience=5) — jab seekhna ruk jaye to learning rate aadha kar do (fine-tuning).
    • ModelCheckpoint(save_best_only, monitor='val_accuracy') — best model save karta rehta hai.
  6. Train: model.fit(...) 50 epochs tak (ya jab tak EarlyStopping na rokay).
  7. Evaluate: validation set pe accuracy & loss, phir classification_report (precision, recall, F1) aur confusion_matrix print hoti hai.
  8. Save: teen cheezein save hoti hain — cow_disease_detector.h5 (model), ...classes.pkl/.json (index→disease mapping), aur ek SavedModel folder.
Important honesty point: Agar examiner exact accuracy % pooche aur tumhare paas number nahi, to bolo: "Validation set pe accuracy, precision, recall aur confusion matrix training ke end mein print hoti hain (classification_report). Final reported value <apni training run wali> thi." Jhooti number mat bolna — agar yaad nahi to "training output mein log hoti hai" keh dena. (Aaj training dobara chala kar exact numbers note kar lo — niche command di hai.)

10. Preprocessing & Prediction (consistency trick)

Ek important design decision: training aur prediction dono mein same preprocessing. Is liye normalization (/255) model ke andar Rescaling layer mein rakha gaya, baahar nahi. Agar baahar bhi /255 kar dete to image do baar normalize ho jati (0–1 ko phir /255) → galat predictions.

# prediction (views.py)
img = load_img(path, target_size=(224,224), color_mode='rgb')
arr = img_to_array(img)              # 0-255 values
arr = expand_dims(arr, axis=0)      # batch shape (1,224,224,3)
# NO /255 here — model ka Rescaling layer karega
preds = model.predict(arr)          # [[0.92, 0.05, 0.03]]
disease = classes[argmax(preds)]    # 'foot-and-mouth'
confidence = max(preds)             # 0.92

13. ⭐ MySQL kyun, MongoDB kyun nahi? (full answer)

Yeh tumhara specific sawaal tha — viva mein bhi aa sakta hai. Strong, defensible answer:

1. Data relational hai, document nahi

Har detection ek user se belong karti hai (User → many Detections). Yeh clear one-to-many relationship hai with a fixed schema. Relational DB (MySQL) exactly isi ke liye bana hai — foreign keys, JOINs, referential integrity (on_delete=CASCADE — user delete to uski detections bhi).

2. Django officially relational DBs ko support karta hai

Django ORM ka first-class support MySQL/PostgreSQL/SQLite ke liye hai. MongoDB ke liye official support nahi — third-party (Djongo) chahiye jo migrations/JWT ke saath buggy aur unstable hota hai. MySQL ke saath migrations, admin panel, auth — sab out-of-the-box chalta hai.

3. ACID transactions & consistency

Medical/health records mein data ka accurate aur consistent hona zaroori hai. MySQL fully ACID-compliant hai (Atomicity, Consistency, Isolation, Durability). Reliability is project ke liye flexibility se zyada important thi.

4. Flexibility ki zaroorat thi → JSONField se mil gayi

Jahan flexible/variable data chahiye tha (symptoms list, treatment steps), wahan MySQL ke native JSON columns (Django JSONField) use kiye. To "schema-less flexibility" ka jo aam faida MongoDB ka hota hai, woh humein relational DB ke andar hi mil gaya — bina relational benefits khoye.

5. Scale appropriate hai

MongoDB ka asal faida tab hai jab data huge-scale, schema-less, ya heavily distributed ho (e.g. logs, IoT streams). Hamara data structured aur moderate-scale hai — MongoDB yahan over-engineering hoti.

One-line jawab: "Mera data structured aur relational hai (user ↔ detections), aur Django relational DBs ko natively support karta hai with ACID guarantees. Jahan flexibility chahiye thi wahan MySQL ke JSON columns use kiye — to mujhe relational integrity + document flexibility dono mil gaye. MongoDB schema-less, huge-scale use-cases ke liye behtar hai, jo is project ki need nahi thi."

14. Authentication & Security (JWT)

  • Register: create_user() password ko Django ke PBKDF2 algorithm se hash karta hai — plain text kabhi store nahi hota.
  • Login: POST /api/token/ (SimpleJWT) → access token (24h) + refresh token (7 days). ROTATE_REFRESH_TOKENS=True.
  • Protected APIs: har request mein Authorization: Bearer <token>; IsAuthenticated ensure karta hai sirf logged-in user apna data dekhe (queries hamesha filter(user=request.user)).
  • JWT kyun (vs session): stateless — server pe session store nahi karna parta, scalable, aur frontend (Vercel) + backend (Railway) alag domains pe hain to token-based auth clean hai.
  • Aur: CORS allowed origins, CSRF trusted origins, file size/type validation, HTTPS (secure cookies jab DEBUG off), WhiteNoise static files, API key .env mein.

General / Architecture

Apna project 30 seconds mein explain karo.

"VetAI Diagnostics ek AI-based web platform hai jo cattle ki bimariyan detect karta hai. User jaanwar ki photo upload karta hai, ek MobileNetV2 CNN model bimari classify karta hai with confidence score. Agar photo na ho to user symptoms select karke rule-based diagnosis le sakta hai. Bimari milne ke baad Google Gemini se real-time treatment, antibiotics aur prevention aata hai. Backend Django REST Framework, database MySQL, frontend React. Saari history aur statistics user ke account mein save hoti hain."

Tumhara tech stack kya hai aur har ek kyun chuna?

Django+DRF (rapid, secure, built-in auth + ORM), React+Vite (fast modern UI), TensorFlow/MobileNetV2 (lightweight image classification), MySQL (relational, ACID, Django native support), Gemini (real-time medical knowledge bina apni medical DB maintain kiye), JWT (stateless auth across separate frontend/backend domains).

Frontend aur backend kaise communicate karte hain?

REST API ke through, JSON over HTTPS. React Axios se requests bhejta hai jisme Authorization: Bearer <JWT> header hota hai. Django DRF token verify karke response JSON deta hai. CORS configured hai taa ke Vercel frontend Railway backend ko call kar sake.

Database (tumhara specific area)

MongoDB kyun use nahi kiya, MySQL kyun?

"Data structured aur relational hai — har detection ek user se foreign key se judi hai. Django relational DBs ko natively support karta hai with ACID guarantees, jabke MongoDB ke liye unstable third-party adapter chahiye. Jahan flexibility chahiye thi (symptoms/treatment lists), wahan MySQL ke native JSON columns use kiye — to relational integrity + document flexibility dono mil gaye. MongoDB schema-less, huge-scale data ke liye behtar hai, jo meri need nahi thi." (Section 13 detail.)

JSONField kyun, alag table kyun nahi banayi symptoms ke liye?

Symptoms/treatment ek detection ke saath hamesha sath padhe jaate hain (kabhi alag query nahi hoti), variable length hote hain, aur unpe complex JOIN/search nahi chahiye. To inhe ek JSON column mein rakhna simple aur fast hai — bewajah normalization aur extra JOINs avoid ho gaye. Agar inpe filtering/reporting chahiye hoti to alag table behtar hoti.

Database mein relationships kaise hain?

Django built-in User table hai. AnimalDetection aur SymptomDiagnosis dono mein user = ForeignKey(User, on_delete=CASCADE) — one-to-many. User delete to uski saari records bhi delete. Performance ke liye (user, created_at) aur disease_name pe indexes hain.

Machine Learning

MobileNetV2 kya hai aur kyun chuna?

Google ka lightweight CNN, depthwise-separable convolutions ki wajah se bohot kam parameters (~3.4M) aur fast inference, lekin acchi accuracy. ImageNet pe pre-trained hai to transfer learning se chhote dataset pe bhi achha kaam karta hai. ResNet/VGG bhaari aur slow hote — low-cost deployment aur chhote dataset ke liye MobileNetV2 ideal tha.

Transfer learning kya hai? Tumne kaise use kiya?

Pre-trained model ka general knowledge reuse karna. Maine MobileNetV2 base (ImageNet weights) ko freeze kiya (trainable=False) aur upar apni custom layers (GlobalAveragePooling → Dense 256 → Dropout → Dense 128 → Dropout → Dense softmax) add karke sirf woh train kiye. Faida: kam data, fast training, achi accuracy, overfitting kam.

Model kitni classes detect karta hai?

"Image CNN model 3 classes detect karta hai: foot-and-mouth, lumpy skin, aur healthy — kyun ke in 3 ka quality image data available tha. Iske ilawa ek symptom-based engine hai jo 93 symptoms ko 26 cattle diseases se match karta hai. Architecture scalable hai — naya data add karke classes barh jaati hain." (Section 3.)

Confidence score kya hai?

Softmax output layer har class ke liye 0–1 probability deta hai (sab ka sum 1). Sab se zyada probability wali class prediction ban-ti hai, aur woh probability hi confidence score hai. Agar <0.4 ho to system warning deta hai ke vet se confirm karein.

Overfitting kaise roka?

(1) Data augmentation (rotation/flip/zoom/shift), (2) Dropout layers (0.5, 0.3), (3) Transfer learning + frozen base (kam trainable params), (4) EarlyStopping with restore_best_weights, (5) train/validation split se monitoring.

Data augmentation kya hai aur kyun?

Training images ko randomly thoda badalna (rotate, flip, zoom, shift) taa ke model alag-alag angle/lighting pe robust bane aur ratta na maare. Effectively dataset bara ho jata hai bina nayi images ke — chhote dataset mein bohot useful.

Loss function aur optimizer kaunsa, kyun?

categorical_crossentropy — multi-class classification ka standard loss (predicted probabilities vs true one-hot label ka difference). Adam optimizer (lr=0.001) — adaptive learning rate, fast aur reliable convergence.

Class imbalance kaise handle ki?

compute_class_weight('balanced') se har class ko uski frequency ke hisaab se weight diya — kam samples wali class ko zyada weight, taa ke model bari class ki taraf biased na ho.

Model ki accuracy kitni hai? Kaise measure ki?

Training ke end mein validation set pe accuracy, loss, aur classification_report (precision, recall, F1) plus confusion matrix nikalti hai. [Yahan apni actual training run wali value bolo — agar yaad nahi to keh do "training output mein log hoti hai, last run mein ~X% thi". Aaj exact number note kar lo.]

Symptom diagnosis ML hai ya nahi?

Nahi, woh rule-based matching hai, deep learning nahi. Input symptoms ko har disease ke known symptoms se match karke ek score deta hai: 0.6×match_ratio + 0.4×coverage, phir top 5 sort karta hai. Image detection wala part deep learning (CNN) hai.

Image ko 224×224 kyun karte ho?

MobileNetV2 ka standard input size 224×224×3 hai (ImageNet pe isi pe train hua). Saari images same size honi chahiye taa ke model ka input fixed rahe.

Normalization (/255) kahan hoti hai?

Model ke andar ek Rescaling(1/255) layer mein — baahar nahi. Is se training aur prediction dono mein same preprocessing guarantee hoti hai. Agar baahar bhi /255 karte to double-normalization se predictions galat ho jate.

Gemini / API

Gemini kyun use kiya, apni database kyun nahi banayi treatment ki?

Veterinary medical knowledge bohot bara aur badalta rehta hai. Gemini real-time accurate, up-to-date treatment/antibiotics/prevention deta hai bina humein ek bari medical database maintain kiye. Reliability ke liye ek local disease_info.json fallback bhi rakha hai jab API fail ho.

Agar Gemini API fail ho jaye to?

Multi-layer fallback: pehle JSON repair, phir compact retry, phir doosre Gemini models, phir local disease_info.json, aakhir mein safe default response. App kabhi crash nahi karti — graceful degradation.

API key secure kaise hai?

.env file mein hai (git mein commit nahi), sirf server-side use hoti hai — frontend pe kabhi expose nahi. VetChat bhi server-side proxy ke through chalti hai. Error logs mein key redact hoti hai.

Security & Deployment

Password kaise store hote hain?

Plain text mein bilkul nahi. Django create_user() PBKDF2 (salted hash) se password hash karta hai. Login pe hash compare hota hai.

JWT kya hai, kyun use kiya?

JSON Web Token — login ke baad ek signed token milta hai jo har request mein header mein jata hai. Stateless hai (server pe session store nahi), scalable, aur alag-alag domains (Vercel frontend / Railway backend) ke beech clean kaam karta hai. Access token 24h, refresh 7 days.

Ek user doosre ka data dekh sakta hai?

Nahi. Har query filter(user=request.user) karti hai, aur IsAuthenticated permission lagti hai. Token se identify hota hai ke kaun request kar raha hai.

File upload validation kaisi hai?

Max 10MB size, aur sirf .jpg/.jpeg/.png/.gif allowed. Invalid ho to 400 error. Image temp file mein process hoti hai phir clean up ho jati hai.

Tough / conceptual

CNN kaise kaam karta hai, simple words mein?

Convolution layers image pe chhote filters slide karke patterns detect karti hain — pehli layers edges/colors, agli layers shapes/textures, gehri layers "disease jaisa pattern". Pooling size kam karti hai. Aakhir mein dense+softmax layer class decide karti hai. Network in filters ki values training ke dauraan khud seekhta hai.

Agar model galat prediction de to?

System confidence score dikhata hai aur low confidence (<0.4) pe warning deta hai ke vet se confirm karein. Disclaimer hai ke yeh diagnostic suggestion hai, professional vet ki jagah nahi. Accuracy improve karne ke liye zyada/behtar training data chahiye.

Singleton pattern kahan use kiya aur kyun?

DiseaseDetectionModel aur DatasetProcessor dono singleton hain. Model (~13MB) aur dataset sirf ek baar memory mein load hote hain, har request pe nahi — is se response fast hoti hai aur memory bachti hai.

Scalability — agar 10,000 users aa jayein?

Stateless JWT auth horizontal scaling allow karti hai (multiple backend instances). MySQL indexes queries fast rakhte hain. Model singleton + caching. Further: model serving alag service mein, DB read-replicas, CDN for static, rate limiting. (Future work.)

Image model 3 classes pe hai to lumpy ke ilawa skin disease ki photo doge to kya hoga?

Model usay teeno mein se kisi closest class mein daal dega (kyun ke softmax hamesha kuch na kuch deta hai), lekin confidence low aayegi. Isi liye low-confidence warning rakhi hai. Yeh ek known limitation hai — out-of-distribution detection future work hai.
